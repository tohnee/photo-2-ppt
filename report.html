01项目概述

本项目解决一个具体问题：给定一张幻灯片照片（投影屏、会议电视、显示器、PDF 截图），重建为可编辑/可归档的数字产物。

提供两条输出路径，共享同一套 OCR 提取与坐标系统：

双输出路径
路径输出适用场景文本图表
HTML 单个自包含 .html 归档、无损保存、Web 浏览、可缩放 真实可选文本 内联 SVG（矢量）或 base64 裁剪
PPTX 可编辑 .pptx 二次编辑、插入现有 PPT、办公协作 原生 TextBox 原生 Table / 图片裁剪

02整体架构

系统采用管道式架构，每个阶段产出独立产物，失败时可单独重试。所有坐标统一在"清洗后图像像素"空间，下游只需一个 scale = 1280 / cleaned_width 即可映射到画布。

关键设计决策

坐标系统一：OCR 输出的 bbox 直接是清洗图像像素坐标，与 Stage 2 人工测量在同一空间，无需额外变换。这是整个管道能"局部修改不互相破坏"的基础。

03四阶段管道详解

Stage 1 — 提取（extract_slide.py）

  • 输入：原始照片（任意分辨率、任意角度）
  • 处理：OTSU 阈值检测亮区 → 四角点提取 → 4 点透视变换 → CLAHE 对比度恢复 → 强制 16:9
  • 输出：slide_clean.jpg（标准化 16:9 图像）
  • 依赖：opencv-python, Pillow

Stage 1.5 — OCR 结构化（ocr_extract.py）

核心阶段。运行 PP-StructureV3 管道，产出机器可读的结构化规格：

# spec.json 结构
{
  "image_path": "slide_clean.jpg",
  "image_size": [1920, 1080],
  "blocks": [
    {
      "type": "title",          # title|text|caption|formula|table|figure|unknown
      "text": "系统架构设计",
      "bbox": [120, 80, 800, 140],  # 清洗图像像素
      "reading_order": 0
    },
    {
      "type": "formula",
      "latex": "E = mc^2",
      "bbox": [...]
    },
    {
      "type": "table",
      "html": "<table><tr><td>...</td></tr></table>",
      "bbox": [...]
    }
  ]
}

Stage 2-3 — 组装

两条分支共享 spec.json，但产出物形态不同：

HTML 组装（assemble_html.py）
  • 文本块 → 真实可选 HTML 文本，绝对定位，颜色/字号从源像素采样
  • 公式/表格/图形 → 原图像素裁剪，base64 内嵌（保持单文件）
  • LaTeX/表格HTML → 保留为 data-* 属性，供矢量路径复用
  • 画布：固定 1280×720，position:absolute 定位（非 flex/grid）
PPTX 组装（assemble_pptx.py）
  • 文本/标题/说明 → 原生 TextBox（可编辑，保留位置/字号/颜色）
  • 表格（HTML 可解析） → 原生 PPTX Table（可编辑单元格）
  • 公式/图形/不可解析表格 → 原图像素裁剪，作为图片嵌入
  • 坐标系：EMU（English Metric Units），1 inch = 914400 EMU

Stage 4 — 验证（render_verify.py）

无头 Chromium 渲染 HTML → 1280×720 PNG，可选与原图生成并排对比图。检查顺序：裁剪溢出 → 碰撞 → 数学符号 → 图标 → 颜色漂移 → 文本保真 → 细节匹配 → 裁剪接缝。

4.2 PP-OCRv5 vs PP-OCRv6

为什么默认用 v5_server？

PP-StructureV3 的官方配置（paddlex/configs/pipelines/PP-StructureV3.yaml）默认使用 PP-OCRv5_server 作为文本层。这是 PaddlePaddle 团队自己的推荐配置，且 v5_server 是"高精度旗舰"，而 v6 只发布了轻量级变体（tiny/small/medium），没有 server 级。

版本变体定位PP-StructureV3 集成
PP-OCRv5server, mobile高精度旗舰 + 轻量官方默认
PP-OCRv6tiny, small, medium下一代轻量改进可选（仅文本层）

v6 按需下载策略：v6 权重不打包进仓库（避免膨胀 1.7 GB 基线），用户可自行下载后丢入 models/ 目录，ocr_extract.py 自动识别。优先级如下（每个 kwarg 取第一个匹配的目录）：

1--det-model / --rec-model CLI 指定的目录（如果存在）
2PP-OCRv6_medium_*（如果存在）
3PP-OCRv6_small_*（如果存在）
4PP-OCRv6_tiny_*（如果存在）
5PP-OCRv5_server_*（仓库打包默认）
6PP-OCRv5_mobile_*（回退）

4.3 离线分发设计

核心目标：首次安装后，OCR 阶段零网络访问。实现机制：

  1. 预下载：setup_paddle.sh 调用 download_paddle_models.py，通过 paddlex 内置下载器（HF → ModelScope → BOS 自动回退）拉取全部 11 个模型到 photo-to-html/models/
  2. 环境变量：运行时设置 PH2H_MODELS_DIR，ocr_extract.py 检测后通过 *_model_dir kwarg 直接挂载本地目录，绕过在线下载器
  3. 格式兼容：_resolve_local_models() 同时支持 PaddleOCR 3.7+ 的 inference.json + inference.pdiparams 和旧版 inference.pdmodel + inference.pdiparams
  4. 完整性校验：manifest.json 记录每个文件的 SHA256，--verify 模式可校验任意副本
  5. 版本控制：大权重文件（*.pdiparams, *.pdmodel）通过 Git LFS 托管，clone 后 git lfs pull 物化
绕过在线下载器的关键

PPStructureV3 的 *_model_dir kwarg 优先级高于 *_model_name。只要本地目录存在且包含 inference.pdiparams + inference.json，就不会触发任何网络请求。

5.2 颜色采样算法

文字颜色从源像素采样是 PPTX 保真度的关键。朴素方法（取 bbox 平均色）在"白底黑字"场景会采样出浅灰色。本项目采用中位数阈值 + 排序回退策略：

def sample_text_color(img, bbox):
    """从文本 bbox 采样墨色，返回 RGB 元组。

    对'亮背景上的稀疏墨迹'鲁棒：当 bbox 中 >80% 是背景时，
    百分位阈值会坍缩到主导背景值。改用中位数亮度的 70% 作为
    阈值（亮背景）或中位数 + 30% 净空（暗背景），若匹配像素
    不足则回退到排序取最极端的 5%。
    """
    import numpy as np
    x1, y1, x2, y2 = bbox
    region = img.crop((x1, y1, x2, y2))
    a = np.asarray(region).reshape(-1, 3)
    lum = a.mean(axis=1)
    median_lum = float(np.median(lum))
    n = len(lum)
    min_ink = max(1, n // 100)  # 至少 1% 像素

    if median_lum >= 128:  # 亮背景 → 墨色偏暗
        thr = median_lum * 0.7
        ink_pixels = a[lum <= thr]
        if ink_pixels.size < min_ink:
            n_ink = max(1, n // 20)  # 最暗 5%
            order = np.argsort(lum)
            ink_pixels = a[order[:n_ink]]
    else:                # 暗背景 → 墨色偏亮
        thr = median_lum + (255 - median_lum) * 0.3
        ink_pixels = a[lum >= thr]
        if ink_pixels.size < min_ink:
            n_ink = max(1, n // 20)
            order = np.argsort(lum)
            ink_pixels = a[order[-n_ink:]]

    r, g, b = ink_pixels.mean(axis=0).astype(int)
    return (int(r), int(g), int(b))
算法要点

① 用中位数（而非均值）判断背景明暗，对稀疏墨迹鲁棒；② 阈值取中位数的 70%（亮）或 +30% 净空（暗），避免百分位坍缩；③ 像素不足时回退到排序取 5%，保证总有结果；④ 表格单元格颜色从整个表格 bbox 采样墨色，统一应用。

07环境准备

7.1 必须预先安装的依赖

要求版本说明
Python 3.9 – 3.12 PaddlePaddle 3.x 无 3.13+ wheel；PaddleOCR 3.7 不支持 3.8。python3 --version 检查

09快速开始

9.1 一键端到端

# 自动模式：图片 → HTML + PPTX，无需 LLM 参与
python3 photo-to-html/scripts/run_pipeline.py photo.jpg \
    --out-dir out --format both --verify

# 输出：
# out/slide_clean.jpg   透视校正后的清洗图
# out/spec.json         OCR 结构化规格
# out/slide.html        自包含 HTML
# out/slide.pptx        可编辑 PPTX
# out/slide_render.png  HTML 渲染验证截图

9.2 分阶段运行

# Stage 1: 提取
python3 photo-to-html/scripts/extract_slide.py photo.jpg --output slide_clean.jpg

# Stage 1.5: OCR
export PH2H_MODELS_DIR=$(pwd)/photo-to-html/models
python3 photo-to-html/scripts/ocr_extract.py slide_clean.jpg --out spec

# Stage 2-3: 组装
python3 photo-to-html/scripts/assemble_html.py spec.json --out slide.html
python3 photo-to-html/scripts/assemble_pptx.py spec.json --out slide.pptx

# Stage 4: 验证
PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers \
    python3 photo-to-html/scripts/render_verify.py slide.html --ref slide_clean.jpg

9.3 v6 按需下载

默认使用 v5_server。若要尝试 v6，下载权重到 models/ 目录即可自动识别：

cd photo-to-html

# 选择变体：medium（最佳精度）| small（均衡）| tiny（最快）
VARIANT=medium

# 方式 A — huggingface_hub（推荐）：
pip install huggingface_hub
python3 - <<EOF
from huggingface_hub import snapshot_download
for task in ("det", "rec"):
    repo = f"PaddlePaddle/PP-OCRv6_${VARIANT}_{task}"
    snapshot_download(
        repo_id=repo,
        local_dir=f"models/PP-OCRv6_${VARIANT}_{task}",
        allow_patterns=["inference.json", "inference.pdiparams",
                        "inference.yml", "config.json"],
    )
    print(f"  OK: models/PP-OCRv6_${VARIANT}_{task}")
EOF

# 重新运行，自动用 v6
python3 scripts/ocr_extract.py slide_clean.jpg --out spec
# -> [ocr] using local weights from .../models (11 model dirs)
#    （v6 优先级高于 v5，自动选中）
强制使用 v5（即使 v6 存在）

若 v6 效果不如 v5，可强制指定：--det-model PP-OCRv5_server_det --rec-model PP-OCRv5_server_rec

核心函数：_resolve_local_models()

离线模式的核心。遍历 PH2H_MODELS_DIR，按优先级匹配模型目录，返回 *_model_dir kwarg 字典：

输入：root（模型目录 Path）, det_model（CLI 指定检测模型名，可选）, rec_model（CLI 指定识别模型名，可选）
输出：{"text_detection_model_dir": "/path/to/PP-OCRv6_medium_det", ...}
逻辑：对每个 kwarg，按候选列表顺序找第一个存在的目录（含 inference.pdiparams + inference.json），找到即 break

核心函数：build_structure()

构建 PPStructureV3 管道。关键逻辑：

  1. 检测 PH2H_MODELS_DIR，存在则调用 _resolve_local_models()
  2. 本地找到的模型通过 *_model_dir 挂载
  3. CLI 指定但本地没有的模型，通过 *_model_name 传递（触发在线下载）
  4. 无 PH2H_MODELS_DIR 时，所有 --det-model/--rec-model 走在线下载
